# Draw Your World v4 · UI / UX 实施合同

日期：2026-11-17。视觉负责人：companion_concept_review。英文主界面，中文协作文档。

## 1. 本轮基准与优先级

用户选定 **艺术海报首页 + 无框白墙工作区**：成熟、极简、留白、不对称，稍微可爱的扁平动物陪伴。取消邮局故事、地图导航、信封/邮票/票据隐喻，不把主流程重新做成左画框右聊天栏。

- 当前构图参考：[implementation-board.png](./implementation-board.png)。实际页面用 HTML、CSS、可操作 canvas 与独立角色素材实现，不把整图用作 UI。
- 参考顺序：用户最新指令 → 本合同及本轮流程合同 → 最新图 → 历史 v3。v3 非视频的功能覆盖继续有效，旧主题文字与排版不再适用。
- 生成图有明确错误：植物只是示例，不是新作默认内容；`QLOP` 含受排除的 P，不能原样实现；不要复制笼统的 `Your drawing is private` 声明。`Pocket Observatory` 这样的趣味名称可保留，但不能替代功能按钮。
- 产品任务直说：`Draw`、`Talk about my drawing`、`Make a record`、`My drawings`、`Share with a professional`。不要求用户理解故事才能完成动作。

## 2. 视觉 tokens

| Token | 值 | 用途 |
| --- | --- | --- |
| White | `#FFFFFF` | 整面工作区和真正导出的绘画底色 |
| Paper | `#F6F1E8` | 首页底色、工作区极窄地沿；不能污染导出图 |
| Ink | `#252722` | 标题、正文、工具与状态；次级文字用 `#62665F` |
| Orange | `#B94D1F` | 首页主动作与少数确认动作；和熊的暖色呼应 |
| Ochre | `#E4AB55` | 低台/工具托，搭配 Ink 字；不用白字 |
| Sage | `#ADB69A` | 小面积地沿/圆面呼应；选中态用深绿 `#4F6345` |
| Blue | `#4774B5` | 仅首页裁切圆面、绘画调色盘或低台极小细节 |

- **绘画与聊天取消整个蓝色侧边/楔形。手机完全没有侧栏几何。** 色彩在低台、角色和一处 sage 小面相互呼应，不靠左右对称装饰平衡。
- 90% 以上创作视野保持白色。没有材质噪点、纸张滤镜、背景渐变、漂浮卡片墙和统一圆角容器。
- 显示字体用 `Georgia, "Times New Roman", serif` 的粗体；正文/控件用 `"Segoe UI", Arial, sans-serif`。无需运行时联网取字。
- 首页字号桌面 `clamp(112px, 13vw, 208px)`、手机 `clamp(76px, 22vw, 112px)`；紧行距约 `.88`。功能页标题桌面 44–64px / 手机 32–42px；正文 16–18px、行高 1.5；辅助最小 13px。
- 大字只集中在首页和少数记录标题。不要每页都铺满巨型标题；操作信息不能为了美术变小。
- 间距基准 8 / 12 / 20 / 32 / 48 / 72。桌面边距 32–56px；手机 20px，工具必要时 12px。阅读宽度 560–640px。
- 主按钮允许浅斜切外形，**文字不斜切、命中区不缩小**；其余动作简洁下划线或工具图标+文字。不把所有按钮做成装饰物。

## 3. 核心空间和跨端规则

### 首页：一张可操作的海报

`Draw / your / world.` 组成非对称字面；蓝色裁切圆面位于上缘，sage 小面在另一边缘呼应。斜白纸面只是首页构图，不能沿用为工作区卡片。熊拿笔与一条装饰线连接 `Start drawing`；次级 `My drawings`，小型 `Menu` 打开 Account / History / Community / Professional support / Pricing。不要完整网站导航条、hero 左文右图、底部营销区或功能卡网格。

手机重新安排字和角色，不等比缩小桌面海报。首次无账号仍须有可达的登录/注册演示分支；继续与直接绘画的守卫由流程合同实现，不把昵称表单塞在海报主视野。

### 绘画：同一幅纯白作品

- 新作固定 **1200 × 1200 逻辑坐标**，纯白且无示例。历史非方形作品保留原宽高比，使用 contain；禁止拉伸、自动裁切。
- 桌面画布居中略偏上，尺寸以可用空间为准，约 `min(64dvh, 可用宽度)`；手机宽度为可用宽度、比例 1:1。1280×720 时工具与主动作仍可见或明确可滚动。
- 无框不等于无限画布：只在真实 canvas 中央显示 `Make your first mark here`，第一笔消失；不可写 `Draw anywhere in the white space` 后让外围白墙无法画。指针命中和实际可绘区域一致。
- 顶边只留 Home / Save drawing / More 等少量动作；底边工具托：Draw / Shapes、颜色、笔粗、橡皮、Undo / Redo、Clear。收纳次要工具可以，但不能删除功能。
- 低台承载主动作 `Look at my drawing` 或已观察后的 `Talk about my drawing`；具体先后遵循流程合同。拒绝 AI 仍可写自己的记录、下载或保存。
- 画布与工具托间留出真实操作空间。熊只在托台端点，不遮工具、不进入可绘范围；桌面约 80–112px、手机约 56–76px 高。
- Draw / Shapes 切换不能悄悄清空已有作品。Clear、新建替换当前未保存草稿需要可取消的明确确认。

### 观察与聊天：画仍在同一个地方

- 没有固定左右栏。作品等比向上移、稍缩小，在下方展开像展品说明的文字。正文左对齐，不能整段居中。
- 桌面作品可见区建议 300–380px 高，正文位于其下，最大 620px，允许横向偏移 3–5vw 保持构图；不得缩成头像。
- `View drawing` 打开可缩放原图；图上选区是可取消的临时标记，不修改原画、不进入导出。
- 当前一两轮对话优先显示；`View conversation` 展开完整历史。没有大型气泡容器，也不能因隐藏历史丢掉可追溯上下文。
- AI 来源要可识别，例如 `Bear · AI companion`；用户原话标 `You`。每轮默认最多一个问题，也允许只回应；有 `Make a record` 和 `Back to drawing`，不要求答满题数。
- 回画保持笔色、笔粗、擦除状态、撤销历史、作品坐标；聊天模式点击作品不能误画。

### 移动端键盘

- 输入框至少 16px 字号，发送按钮保持可见、键盘可达；使用实际可用视口，不能把设计图的键盘当 UI。
- 键盘出现先隐藏角色、台脚和地沿，再缩小作品预览；绘画坐标不变。完整作品仍可查看，必要时 `View drawing` 展开后收起键盘。
- 约 390×844 下，键盘开启时预览建议 144–200px 高；极矮屏优先保留输入和 `View drawing`，不要硬塞四个固定高度区域。
- 可滚动区与固定输入区不能互相遮盖；焦点框、最后一条回复、发送错误都在可视区域。不能以 `overflow:hidden` 隐藏长内容。

## 4. 状态布局与关系

这些是可返回的状态，不是强制完成的问卷。核心关系：`Home → Draw → AI permission → Observe → optional Talk → Make a record → Review summary → optional Type → Save → History`。**Draw / Talk 都可直接 Save drawing；不聊、不选类型也能完成。** AI不同意时直接走本人记录，不制造 AI 观察。

| 状态 | 必须显示的内容与布局 | 主要动作与退路 |
| --- | --- | --- |
| AI permission | 小型就地面板，画保留可见；说明画和对话会交给已配置 AI 处理 | Allow AI / Continue without AI；保存许可独立，不默认勾选 |
| Observe | 原作上方/中上，下面 1–3 条可核对的可见事实；本人解释分开 | Correct observation / Talk about my drawing / Make a record / Back to drawing |
| Talk | 作品、当前回应、输入，纵向连续 | Send / Make a record / View conversation / Back to drawing |
| Make a record | 作品与标题，下方本人一句话、可跳过的自评；可选 Short note / Longer note / Picture only | Review summary；仅进入编辑，不意味着已保存 |
| Review summary | 原作小预览 + 可编辑正文；来源清楚，AI草稿不能标为本人确认 | Edit / Confirm summary / Keep only my own words；改动后需重新确认 |
| Type | 大但简洁的类型文字和小图形，作品仍可回看；一行可见依据 | Change / Keep this type / Skip；不能挡住保存 |
| Save review | 标题、保存目的地、勾选的保存项目、原图预览 | Save drawing / Save record；Download；Cancel。没有成功前打勾 |
| Saved | 简明真实状态、目的地、时间；不再混放待确认 checkbox | View my drawings / Keep drawing / Add a conversation copy；后者单独执行并单独反馈 |
| History | 像艺术目录，图为主体；桌面疏密交错、手机一列/合适时两列；日期与标题直接相邻 | 打开、下载、明确删除、重新创作副本、选择专业支持 |
| Work detail | 原图、本人文字、确认总结、此次类型分别标注；无记录项不假装生成 | Edit a copy / Download drawing / Share with a professional；原件保持 |
| Support | 三个清楚、平等的文本入口，不能强推专业支持 | Community / Professional support / Finish |

保存目的地必须按真实实现写：本地 browser 存储用 `Saved in this browser`；服务器会话存储按实际描述。不能无依据承诺私密云端账户、跨端同步或已分享。原图与记录分别保存，保存状态不能由角色动画代替。

## 5. 当次趣味绘画类型

- 标题 `Today's drawing type`。定位是这次作品的趣味命名，不是用户人格；采用 **16 种平等的趣味名称**，允许幽默、无厘头和艺术化联想，如 `Pocket Observatory`。不能把全部趣味名称收缩为普通画法标签。
- 按用户最新选择，可附 **4 位新字母代码**，但必须完全避开 MBTI 使用的 `E I S N T F J P`，例如 `UCAV` / `OGDZ`。代码是小的索引，趣味名称为主；不画 MBTI 维度坐标、人格量表、诊断、分数高低或成长等级。最终 16 种名称/代码与数据合同统一。
- 依据只用可核对画面与本人已确认的话，如 `You left most of the page open and gathered a few shapes near the edge.` 不把颜色解释成情绪，不由笔触推测性格。
- 配一句 `A playful name for this drawing, not a personality test. Change it or leave it out.` 用户可换名、选别项或跳过；不同作品可不同，不出现永久个人徽章。趣味联想用 `A playful suggestion` 与画面事实/本人原话区分，不能把任意命名包装成科学结论。
- 总结或画作变化后，旧类型标为待复核或由用户主动重新生成，不悄悄替换已确认记录。AI不可用时明确提供本人选择，不假装分析完成。
- 分享专业人士时默认不包含趣味类型；仅真实选中的、本人已确认的内容进入预览。

## 6. 其余 PDF 功能的同主题承接

功能不能因为去故事线而消失。以下界面沿用白底、清楚标题、展册式留白；复杂表单可用正常表单结构，但不引回邮局故事或营销网站。

| 功能 | v4 呈现要求 |
| --- | --- |
| 登录/注册、Account | 清楚的演示身份/实际账号说明；有返回与退出，不能假装真实认证 |
| Shapes | 与自由绘画共用白墙，形状工具展开于低台；可选、拖动、缩放、旋转、删除、撤销 |
| Mood history | Week / Month / Year；仅来自本人自评，空状态与 Example 明确分开，不画虚假改善趋势 |
| Community | Write → Preview → Confirm demo post → Withdraw；公开发布与保存是不同授权 |
| Professional support | 提供者、资质/演示身份、价格、时长、可预约时间明确；文字/语音/线下都可达 |
| Share with a professional | 接收方先显示；Drawing / My words / Confirmed summary 逐项默认不选，实时展示接收方看见的确切内容；不分享也可继续 |
| Interview / booking | 选择方式与时间 → 复核费用/授权 → 明确确认演示预约 → 状态页；无真实扣费就明确 Demo |
| Provider view | 只显示所选项目；可回去撤回单项或取消；未经确认总结不进入分享；不以趣味类型冒充专业背景 |
| Text / Voice / In person | 文字可输入；语音预览不可假装通话成功；线下显示预约信息；结束有返回 |
| Pricing / Finish | 免费与付费边界、原图保存状态直说；退出无需评分、无需给动物告别 |

视频生成与相关等待页完全排除，没有残留死入口。真实外发/预约/付款仅在本轮明确接入且经授权时可执行，否则呈现为可操作的本地演示。

## 7. 角色与动效

用户希望角色姿势有变化，可偶尔有其他伙伴；变化服务于状态，不引入照料负担。

| 状态 | 角色姿势/动作 |
| --- | --- |
| Home | 熊拿笔，装饰线引向 Start drawing |
| Draw | 熊安静坐着，最多进入时一次短动作，不跟着每笔蹦跳 |
| Observe / Talk | 熊朝向作品或听的姿势；等待状态仍用文字明确 |
| Record / Review | 熊看一张纸，不能替用户点头确认含义 |
| Saved | **真实成功后**短暂收纸，再静止；失败用文字与重试 |
| History | 偶尔狗伙伴在边缘；一次访问角色固定，不能每次渲染随机换 |

- 成熟扁平轮廓，少色、无腮红闪光、无贴纸描边、无毛绒 3D。只使用独立透明资产，不能切下整张界面充当角色。
- `Hide companion` 可以隐藏；无喂养、打卡、亲密度、角色失落或催促。角色不能挡画布/工具/输入，也不把鼠标区域截走。
- 主要转场：Draw → Talk 时同一作品等比上移，工具收拢，下面出现回应与输入；约 280–380ms。未操作时保持安静。
- 尊重 `prefers-reduced-motion`：直接换状态/淡入，不移动画作、不弹跳；键盘聚焦与成功文案完全不依赖动画。

## 8. 实施验收门槛

截图检查 1440×900、1280×720、390×844、360×740；再用实际输入焦点观察手机键盘可用视口，不能只依据静态图验收。

1. 首屏一眼是艺术海报；绘画/聊天不是左画右栏、整图背景或居中圆角卡；手机无蓝边。
2. Start 后空白；原作从 Draw → Observe → Talk → Record → Saved 的线条、比例、颜色相同，返回工具状态未丢；导出无台子/动物/提示/选区。
3. 工具、发送、Back 与 Save 在小屏可达；长聊天/长总结可滚动；焦点可见、控件至少 44px 命中区、颜色不是唯一选中提示。
4. 拒绝 AI、跳过聊天/自评/类型、直接保存、失败重试各自可完成；没有假识图/假保存/假分享。
5. 用户可纠正总结；趣味类型有明确本次范围，事实依据与趣味联想分开；16 类无高低，新字母不含 `E I S N T F J P`；未经确认内容不进入专业预览。
6. 保存前能说清保存哪些、保存到哪里；保存后能在历史打开；后续加存对话是独立动作；删除/撤回即时反映。
7. 熊姿势确实随状态变化，静态创作时不扰动；角色隐藏/减少动态后功能完整。

这份规范给出的是待验证的设计假设。视觉贴合不等于已证明情绪改善、可用性或治疗价值；首次真实走查重点验证：能否开始画、是否看得清画、是否知道保存/分享了什么。
